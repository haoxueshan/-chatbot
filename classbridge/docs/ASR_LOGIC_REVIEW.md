# 语音识别逻辑检查 · 2026-11-02

本次沿浏览器采音、PCM转发、阿里云事件适配、字幕版本、翻译、停止/恢复及辅助校正检查代码。下述缺陷由隔离测试复现；不能因此判定它们就是用户课堂中所有错字或缺句的原因。

## 已修复

1. **定稿被迟到中间结果降级。** 后端原先对每次回调都增加source_revision，同句final后到达的partial会变成更高版本；前端据此重新创建临时字幕。现在后端忽略该类partial，前端也拒绝用更高的临时版本降级稳定原文。基于稳定新版本的流式翻译仍正常显示。
2. **重复事件制造版本和后台任务。** 空结果、完全重复的中间结果不再增加版本；同一stream/sentence、原文和时间戳的已见定稿去重，即使夹在其他定稿版本之后重到，也不重新投递翻译、向量或辅助校正。确实不同的定稿仍保留为新版本。上游没有原文修订序号，无法推断一个未曾见过的不同final到底是否过期；不同识别任务依靠stream_id隔离。
3. **旧任务事件影响新录音。** 原前端只以event_seq判断停止事件，且旧processing.failed可直接停麦克风。现在同时校验request_id、stream_id、请求前游标，并把身份保留到收尾结束。开始拒绝、处理中、失败、停止事件由后端带上request_id；旧任务的迟到/重放事件继续可供历史记录处理，但不会停止新采音或改写当前计时。后台翻译/校正失败不作为采音失败。
4. **握手与清理。** task-started必须对应本次task_id才能放行音频；收尾会取消并等待临时翻译任务退出，然后清空任务引用。

涉及代码：`backend/app/ws/live.py`、`backend/app/providers/aliyun.py`、`frontend/src/lib/events.ts`、`frontend/src/lib/captureEvents.ts`、`frontend/src/lib/useLive.ts`。

## 已核对的正常路径

- AudioWorklet按输入设备采样率连续混合声道、低通重采样至16 kHz，以PCM16LE发出320采样/640字节的20ms帧。48/44.1kHz、分块连续性、抗混叠和声道混合有自动测试。音量来自实际采样，不用MIME重命名转换。
- 浏览器先获取设备但暂不发PCM，收到本次识别服务ready才开始传输。停止立即释放设备，已提交音频经队列发送，finish-task后继续接收最终结果，直到task-finished；超时或积压记录缺口，不生成模拟字幕。
- 20ms是传输帧，不是断句。程序没有本地按音量切掉静音，也未传自定义max_sentence_silence，当前使用官方默认800ms。断句参数未在本次修改。
- 韩英语种提示、热词和背景在新上游任务开始时读取。中途修改设置要等下次开始，ASR与中文翻译目标分开。没有依据支持把人名错字直接归因为断句太快。
- 原文定稿、事件与后台任务outbox在同一事务保存。旧来源译文不能覆盖新版本。辅助推测只作为待确认建议，接受后创建人工校正版本，原文可追溯；不自动将猜测加入下一次ASR热词。

官方复核：[客户端事件与断句参数](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-streaming-client-events)、[服务端事件与句子标识](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-streaming-server-events)，核验日期2026-11-02。

## 验证和边界

- 新增后端测试先复现2项失败，前端先复现1项失败，再修复。后端完整85项通过；最后补充的跨修订重复定稿检查另以`test_live_ordering.py`复验。前端29项通过，TypeScript/Vite生产构建通过。
- 本次检查没有新增真实模型调用、没有重启正在运行的用户后端，也没有进行实体Safari或真实韩语词错率测试。测试替身不能证明网络、拾音或云端声学识别准确率。
- 正常停止会丢弃尚未组成完整20ms帧的采样及重采样滤波器的短尾部；不是样本级无损停止。此边界不足以解释长时间原文缺失，当前也没有证据表明它造成了用户的人名错字。原始音频仅包含服务器收到的帧。
- 要启用修复，在停止当前录音后，重启PyCharm中的`backend/main.py`，刷新iPad页面，再手动开始录音。不需要迁移数据库或重新填写密钥。

韩语准确率仍需同一段录音与正确文本对照，分别比较原文错字、漏句和中文翻译；界面的延迟和电平只用于链路诊断，不当作识别置信度。
